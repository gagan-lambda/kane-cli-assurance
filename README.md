
# kane-cli Assurance

Requirements-linked, evidence-sealed browser test suite authored via the [kane-cli assurance lifecycle](https://www.testmuai.com/docs/kane-cli-assurance).

Drop a PRD into `docs/`, run the assurance commands, and every test is permanently linked to the acceptance criterion it verifies.

---

## Quick start

### Prerequisites

- kane-cli 0.8.1 or later — `npm install -g @testmuai/kane-cli@latest`
- Authenticated LambdaTest account — `kane-cli whoami`

### One-time setup (per PRD)

```bash
# 1. Ingest your PRD and extract use-cases
kane-cli context ingest docs/<your-prd>.md --mode agent

# 2. Review and approve extracted use-cases
kane-cli context list --json --inferred
kane-cli context review --approve <uc-id> ...

# 3. Design tests for each approved use-case
kane-cli design tests --use-case <uc-id> --mode agent --max 8

# 4. Review and approve the design
kane-cli context review --approve <ac-id> ... <sc-id> ... <t-id> ...

# 5. Fill in test variable values
#    Edit .testmuai/variables/assurance.json (generated by the design step)

# 6. Author tests (first run — opens a real browser)
kane-cli testrun run --from-context <t-id1>,<t-id2>,... --parallel 3 --headless
```

### Replay (CI / subsequent runs)

```bash
# By file paths (default in CI)
kane-cli testrun run .testmuai/tests/ --parallel 3 --headless

# Or by context IDs
kane-cli testrun run --from-context <t-ids> --parallel 3 --headless
```

## The loop at a glance

```
PRD  →  Ingest  →  Extract  →  Review  →  Design  →  Author  →  Cover
```

| Stage | Command | What happens |
|---|---|---|
| **Capture** | `kane-cli context ingest docs/<prd>.md --mode agent` | Snapshot PRD into `.context/` |
| **Extract** | _(runs automatically on 0.7.1+)_ | AI proposes use-cases with cited evidence |
| **Review** | `kane-cli context review --approve <ids>` | Promote use-cases to trusted |
| **Design** | `kane-cli design tests --use-case <id> --mode agent --max 8` | Generate ACs, scenarios, runnable `*_test.md` |
| **Author** | `kane-cli testrun run --from-context <ids> --parallel 3 --headless` | Author in a real browser, seal evidence |
| **Measure** | `kane-cli cover gaps` | Coverage ribbon: designed % x proven % |
| **Maintain** | `kane-cli maintain reconcile --from docs/<prd>.md --source-id <id> --mode agent` | Reconcile when the PRD changes |

## Project structure

```
.
├── docs/
│   └── <your-prd>.md              # Drop your PRD here — one file per product
├── .testmuai/
│   ├── tests/
│   │   └── *_test.md              # Generated test files (one per scenario)
│   └── variables/
│       └── assurance.json         # Test data — fill in values, commit non-secrets
├── .github/
│   └── workflows/
│       └── assurance.yml          # CI workflow — needs LT_USERNAME, LT_ACCESS_KEY, KANE_PROJECT_ID, KANE_FOLDER_ID
├── .context/                      # Assurance store — gitignored, do not edit
├── .gitignore
└── README.md
```

> `.context/` is gitignored. Collaborators run `context ingest` locally to rebuild their store from the committed PRD.

## CI — GitHub Actions

The workflow at `.github/workflows/assurance.yml` triggers on:
- **Push to `main`** when `docs/` or `.testmuai/tests/` change
- **Pull request** to `main`
- **Manual dispatch** — pick a PRD, specific test IDs, and parallelism

### Required secrets

Add these in **Settings → Secrets and variables → Actions**:

| Secret | Where to find it |
|---|---|
| `LT_USERNAME` | LambdaTest dashboard → Profile |
| `LT_ACCESS_KEY` | LambdaTest dashboard → Profile |
| `KANE_PROJECT_ID` | `kane-cli projects list` → copy the `id` field |
| `KANE_FOLDER_ID` | `kane-cli folders list --project <id>` → copy the `id` field |

`KANE_PROJECT_ID` and `KANE_FOLDER_ID` are needed for evidence packs to be uploaded to KaneAI and linked in the job summary. Without them, evidence is still saved as a workflow artifact but no KaneAI link appears.

### What the workflow does

1. Auto-detects the PRD in `docs/` (or uses the `prd_file` input)
2. Ingests it into a fresh local store
3. Discovers all `*_test.md` files under `.testmuai/tests/` and runs them in parallel with `--headless`
4. Posts a **job summary** with:
   - Pass/fail totals and per-test results table
   - Direct link to the execution on the KaneAI dashboard (when evidence upload succeeds)
   - Coverage ribbon by use-case
5. Uploads evidence packs as workflow artifacts (retained 30 days)

### Manual trigger inputs

| Input | Default | Description |
|---|---|---|
| `prd_file` | _(auto-detect)_ | PRD path relative to repo root |
| `tests` | _(all)_ | Comma-separated IDs, e.g. `t-1,t-2` |
| `parallel` | `3` | Parallel workers |

## Adding a new PRD

1. Drop the file into `docs/`
2. Run the one-time setup commands above
3. Commit the generated `*_test.md` files and `assurance.json`
4. Push — the workflow picks up the new tests automatically

---

## When the PRD changes

Do **not** re-ingest directly. Use reconcile — it versions the source and triages the fallout:

```bash
kane-cli maintain reconcile \
  --from docs/<your-prd>.md \
  --source-id <source-id> \
  --mode agent
```
